A1구독 선택 · 변수 · 도우미 함수

소요 약 2분

실습용 구독을 선택하고, 이후 모든 단계에서 쓰는 변수를 정합니다. 변수 이름은 22장 가이드의 스니펫과 같아서(RG · AOAI · LAW · VM …) 가이드의 명령을 그대로 붙여 넣을 수 있습니다.

① 구독과 확장 설치
az login                                        # 이미 로그인되어 있으면 생략 (Cloud Shell 은 불필요)
export SUB="<구독 ID>"                          # ← 실습용 구독 ID 로 바꿉니다 (az account list -o table)
az account set -s "$SUB"
for e in application-insights log-analytics scheduled-query monitor-control-service; do az extension add -n $e -y 2>/dev/null; done
for p in Microsoft.CognitiveServices Microsoft.Insights Microsoft.OperationalInsights Microsoft.Compute Microsoft.Network Microsoft.Storage Microsoft.AlertsManagement; do az provider register -n $p >/dev/null; done
② 변수 · 파일 저장 · 도우미 함수 (vmrun, kq)
export LOC=koreacentral
export SFX=$(LC_ALL=C tr -dc 'a-z0-9' </dev/urandom | head -c5)      # 이름 충돌을 피하는 5자리 접미사
export RG=rg-lablog-$SFX LAW_NAME=law-lablog-$SFX APPI=appi-lablog-$SFX AOAI=oai-lablog-$SFX ST=stlablog$SFX
export DEP=gpt41mini VNET=vnet-lablog SNET=snet-vm NSG=nsg-lablog-vm PIP=pip-lablog-vm VM=vm-lablog-rhel
export MAIL="<알림 받을 이메일>"                                      # ← 본인 메일 (B6 알림 수신)
# 22장 가이드의 변수 이름과 같게 맞춰 둔 값
export LAW=/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.OperationalInsights/workspaces/$LAW_NAME
export VM_RG=$RG AOAI_HOST=$AOAI.openai.azure.com
export TAGS="purpose=aoai-logging-lab created=$(date +%F)"
# 새 터미널에서도 이어서 쓰도록 파일로 저장합니다 (다시 열 때: source lablog.env)
cat > lablog.env <<EOF
export SUB="$SUB" LOC=$LOC SFX=$SFX RG=$RG LAW_NAME=$LAW_NAME APPI=$APPI AOAI=$AOAI ST=$ST
export DEP=$DEP VNET=$VNET SNET=$SNET NSG=$NSG PIP=$PIP VM=$VM MAIL="$MAIL"
export LAW=$LAW VM_RG=$VM_RG AOAI_HOST=$AOAI_HOST TAGS="$TAGS"
EOF
cat >> lablog.env <<'EOF'
# VM 에서 스크립트 실행 (SSH 없이 az vm run-command 사용). 사용: vmrun [KEY=값 ...] <<'X' ... X
vmrun() { local s; s="$(cat)"; if [ $# -gt 0 ]; then az vm run-command invoke -g "$RG" -n "$VM" --command-id RunShellScript --scripts "$s" --parameters "$@" --query "value[0].message" -o tsv; else az vm run-command invoke -g "$RG" -n "$VM" --command-id RunShellScript --scripts "$s" --query "value[0].message" -o tsv; fi; }
# Log Analytics 쿼리 실행 (사용: kq '<KQL>')
kq() { : "${WSID:=$(az monitor log-analytics workspace show -g "$RG" -n "$LAW_NAME" --query customerId -o tsv)}"; az monitor log-analytics query -w "$WSID" --analytics-query "$1" -o table; }
EOF
source lablog.env
echo "RG=$RG  AOAI=$AOAI  VM=$VM"

도우미 함수

vmrun 은 VM 안에서 실행할 스크립트를 표준입력(heredoc)으로 받아 az vm run-command 로 실행하고, kq 는 Log Analytics 쿼리를 실행해 표로 보여 줍니다. VM 에 값을 넘길 때는 vmrun KEY=값 형식을 쓰며, ; 처럼 셸 특수문자가 들어간 값(예: 연결 문자열)은 base64 로 넘깁니다(B3 참고). az 는 표의 열을 알파벳순으로 보여 주므로 아래 ‘예상 결과’와 열 순서가 다를 수 있습니다.

# R3_aoai_call_log.py - AOAI 호출 1회(시도)마다 JSON 1줄을 남기는 헬퍼. 프로젝트에 한 번 추가합니다.
# 요구: Python 3.9+ / openai 패키지 (AzureOpenAI). 프롬프트·응답 본문은 기록하지 않습니다(메타데이터만).
import json, logging, threading, time, uuid
from contextlib import contextmanager

log = logging.getLogger("aoai.call")       # 파일·App Insights(R4)로
_lock, _busy = threading.Lock(), 0
ERR = {"APITimeoutError": "client_timeout"}    # 그 외 예외는 "error"

@contextmanager
def call_log(**fields):
    global _busy
    with _lock:
        _busy += 1
        n = _busy                       # 시작 시점의 동시 호출 수
    rec = {"event": "aoai_call", "cid": str(uuid.uuid4()),
           "inflight": n, **fields}
    t0 = time.perf_counter()
    try:
        yield rec
        rec["outcome"] = "ok"
    except Exception as e:              # 기록 후 예외는 그대로 전달
        rec.update(outcome=ERR.get(type(e).__name__, "error"),
                   error=type(e).__name__,
                   status=getattr(e, "status_code", None),
                   request_id=getattr(e, "request_id", None))
        raise
    finally:
        with _lock:
            _busy -= 1
        rec["total_ms"] = round((time.perf_counter() - t0) * 1000)
        log.info(json.dumps(rec, ensure_ascii=False))
EOF

#!/bin/bash
# R7_aoai_probe.sh - 1분마다 실행하는 합성 probe (VM 안/밖 어디서나 같은 스크립트 사용)
#   (1) AOAI 소형 호출(max_tokens=1)  (2) VM 로컬 앱 URL  → 구간별 시간을 JSON 1줄로 기록
#   기록 위치: syslog(local5) → Azure Monitor Agent(R5) → Log Analytics 'Syslog' 테이블, 그리고 표준 출력
#   필요: curl(7.29 이상), awk, logger  |  설정: /etc/aoai-probe.env (R7_aoai-probe.env.sample 참고)
set -u
. "${PROBE_ENV:-/etc/aoai-probe.env}"
ROLE="${PROBE_ROLE:-vm-inside}"; SLOW_MS="${SLOW_MS:-8000}"; API_VER="${AOAI_API_VERSION:-2024-10-21}"

emit() {  # $1=대상  $2=curl 종료코드  $3=write-out 문자열 (curl 시간값은 누적이므로 차이를 구해 구간별로 기록)
  IFS="|" read -r dns tcp tls ttfb total code ip conns <<<"$3"
  local line
  line=$(awk -v role="$ROLE" -v tgt="$1" -v rc="$2" -v code="${code:-0}" -v ip="${ip:-}" -v cn="${conns:-0}" \
    -v d="${dns:-0}" -v c="${tcp:-0}" -v t="${tls:-0}" -v f="${ttfb:-0}" -v T="${total:-0}" 'BEGIN{
      tcp_ms = (c > d) ? c - d : 0; tls_ms = (t > c) ? t - c : 0; base = (t > 0) ? t : c;
      wait_ms = (f > base) ? f - base : ((f == 0 && T > base) ? T - base : 0);
      printf "{\"event\":\"aoai_probe\",\"role\":\"%s\",\"target\":\"%s\",\"rc\":%d,\"code\":\"%s\",\"dns_ms\":%d,\"tcp_ms\":%d,\"tls_ms\":%d,\"wait_ms\":%d,\"total_ms\":%d,\"ip\":\"%s\",\"new_conns\":%d}",
             role, tgt, rc, code, d*1000, tcp_ms*1000, tls_ms*1000, wait_ms*1000, T*1000, ip, cn }')

C2요청 한 건씩 대조 — 앱이 잰 시간 vs AOAI 가 잰 시간

가이드의 핵심 분석 · 앱 로그(R3)와 AOAI 로그(R1)를 요청 ID 로 조인

앱 로그의 apim_request_id(응답 헤더 apim-request-id)가 AOAI 로그의 CorrelationId 와 같습니다(실측 확인). 그래서 요청 단위로 앱 시간 − AOAI 시간 = 앱↔AOAI 사이(네트워크·클라이언트)에서 쓴 시간을 구할 수 있습니다.

kq '
let app = AppTraces
    | where TimeGenerated > ago(1d) and Message has "aoai_call"
    | extend r = parse_json(Message)
    | project t = TimeGenerated, apim = tostring(r.apim_request_id),
              outcome = tostring(r.outcome), app_ms = toint(r.total_ms);
AzureDiagnostics
| where TimeGenerated > ago(1d) and Category == "RequestResponse"
| project CorrelationId, status = ResultSignature, aoai_ms = DurationMs
| join kind=inner app on $left.CorrelationId == $right.apim
| project t, outcome, status, app_ms, aoai_ms, gap_ms = app_ms - aoai_ms
| order by gap_ms desc
| take 50
'
