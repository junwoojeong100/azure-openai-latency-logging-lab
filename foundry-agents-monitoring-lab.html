foundry/scripts/connect-appinsights.sh — 연결 훅이 실행하는 스크립트 (아래 ‘모니터링 설정’ 전부)
#!/bin/sh
# Foundry 프로젝트에 Application Insights 를 만들어 연결한다.
# 연결만 되어 있으면 프롬프트·호스티드 에이전트의 서버 쪽 트레이스가 코드 변경 없이 쌓인다.
set -eu
RG="$AZURE_RESOURCE_GROUP"; LOC="$AZURE_LOCATION"
LAW="law-$AZURE_ENV_NAME"; APPI="appi-$AZURE_ENV_NAME"
PROJECT_ID="/subscriptions/$AZURE_SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.CognitiveServices/accounts/$AZURE_AI_ACCOUNT_NAME/projects/$AZURE_AI_PROJECT_NAME"

az monitor log-analytics workspace create -g "$RG" -n "$LAW" -l "$LOC" -o none
az monitor app-insights component create -g "$RG" -a "$APPI" -l "$LOC" -o none \
  --workspace "$(az monitor log-analytics workspace show -g "$RG" -n "$LAW" --query id -o tsv)" --kind web --application-type web
APPI_ID=$(az monitor app-insights component show -g "$RG" -a "$APPI" --query id -o tsv)
CS=$(az monitor app-insights component show -g "$RG" -a "$APPI" --query connectionString -o tsv)

az rest --method put -o none --url "https://management.azure.com$PROJECT_ID/connections/$APPI?api-version=2025-04-01-preview" \
  --body "{\"properties\":{\"category\":\"AppInsights\",\"target\":\"$APPI_ID\",\"authType\":\"ApiKey\",\"isSharedToAll\":true,\"credentials\":{\"key\":\"$CS\"},\"metadata\":{\"ApiType\":\"Azure\",\"ResourceId\":\"$APPI_ID\"}}}"

# 호출자에게 Foundry User(구 Azure AI User), 프로젝트 관리 ID 에게 Log Analytics Reader
az role assignment create -o none --assignee-object-id "$(az ad signed-in-user show --query id -o tsv)" --assignee-principal-type User \
  --role 53ca6127-db72-4b80-b1b0-d745d6d5456d --scope "$PROJECT_ID"
az role assignment create -o none --assignee-object-id "$(az rest --method get --url "https://management.azure.com$PROJECT_ID?api-version=2025-04-01-preview" --query identity.principalId -o tsv)" \
  --assignee-principal-type ServicePrincipal --role 73c42c96-874c-492b-b04d-ab87d138a893 --scope "$APPI_ID"
echo "Application Insights connected: $APPI"
foundry/src/report-maf-agent/main.py — 호스티드 에이전트 전체 (텔레메트리 코드 없음)
import os

from agent_framework import Agent
from agent_framework.foundry import FoundryChatClient
from agent_framework_foundry_hosting import ResponsesHostServer
from azure.identity import DefaultAzureCredential

agent = Agent(
    client=FoundryChatClient(
        project_endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        model=os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"],
        credential=DefaultAzureCredential(),
    ),
    instructions="You explain how to write business reports. Answer in Korean.",
    default_options={"store": False},
)

if __name__ == "__main__":
    ResponsesHostServer(agent).run()

"""에이전트를 여러 번 호출하고, 호출마다 JSON 한 줄(클라이언트가 잰 시간 · 응답 ID · 트레이스 ID)을 출력한다.

사용: python invoke_agents.py <에이전트 이름> [횟수=3] [short|long] [new|same]
  new  : 호출마다 새 대화 (호스티드 에이전트는 매번 cold start)
  same : 하나의 대화를 재사용 (첫 호출만 cold, 이후 warm)
"""
import json
import os
import secrets
import sys
import time

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

PROMPTS = {
    "short": "보고서 첫 문단은 어떻게 쓰나요? 한 문장으로 답해줘.",
    "long": "일간 업무 보고서를 쓰는 방법을 한국어 700자 분량으로 자세히 설명해줘.",
}
name = sys.argv[1]
count = int(sys.argv[2]) if len(sys.argv) > 2 else 3
prompt = PROMPTS[sys.argv[3] if len(sys.argv) > 3 else "short"]
same = (sys.argv[4] if len(sys.argv) > 4 else "new") == "same"

project = AIProjectClient(endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"], credential=DefaultAzureCredential(), allow_preview=True)
client = project.get_openai_client(agent_name=name)
conversation = client.conversations.create().id if same else None

for i in range(1, count + 1):
    trace_id = secrets.token_hex(16)
    options = {"conversation": conversation} if conversation else {}
    started = time.perf_counter()
    response = client.responses.create(
        input=prompt,
        extra_headers={"traceparent": f"00-{trace_id}-{secrets.token_hex(8)}-01"},
        **options,
    )
    usage = response.usage
    print(json.dumps({
        "agent": name, "i": i, "ms": round((time.perf_counter() - started) * 1000),
        "status": response.status, "response_id": response.id, "trace_id": trace_id,
        "input_tokens": usage.input_tokens if usage else None, "output_tokens": usage.output_tokens if usage else None,
        "error": response.error.message[:80] if response.error else None,
    }, ensure_ascii=False))

C3느린 호출은 어디서 느린가 — 모델 · 에이전트 런타임 · cold start

원본 가이드의 C2(앱 vs AOAI 대조)에 해당

원본에서는 앱이 잰 시간과 AOAI 가 잰 시간의 차이로 “느린 곳이 앱 쪽인가 AOAI 쪽인가”를 가렸습니다. 여기서는 같은 질문을 두 쿼리로 풉니다.

  • 프롬프트 에이전트: invoke_agent(실행 전체) − chat(모델 호출) = 에이전트 런타임 오버헤드. 정상일 때는 수백 ms 입니다.
  • 호스티드 에이전트: 시작 지연을 4단계(platform_preprocessing · infra_setup · container_readiness · container_response)로 쪼갠 속성이 요청 스팬에 자동으로 붙습니다.
프롬프트 에이전트 — 모델 시간을 뺀 오버헤드가 큰 실행 TOP 10
kq '
let spans = dependencies
    | where timestamp > ago(1h) and cloud_RoleName == "responsesapi" and customDimensions["gen_ai.agent.name"] == "report-prompt-agent";
spans
| where customDimensions["gen_ai.operation.name"] == "invoke_agent"
| project operation_Id, timestamp, run_ms = duration
| join kind = inner (spans | where customDimensions["gen_ai.operation.name"] == "chat" | project operation_Id, model_ms = duration) on operation_Id
| extend overhead_ms = run_ms - model_ms
| top 10 by overhead_ms desc
| project timestamp, trace_id = operation_Id, run_ms = round(run_ms), model_ms = round(model_ms), overhead_ms = round(overhead_ms)
'

  • 그래서 호스티드 에이전트를 쓸 때는 세션(대화)을 재사용하고 idle 시간을 맞추는 설계가 지연에 직접 영향을 줍니다(invoke_agents.py … same).

D1알림 2개 만들기 — 느린 실행 · 실패한 실행

소요 약 15초 · 원본 가이드의 R8 에 해당

Application Insights 를 대상으로 하는 로그 알림 2개와 수신 그룹을 만듭니다. 느린 실행은 cold start 시간을 더한 총 시간이 8초를 넘는 실행(프롬프트 · 호스티드 공통), 실패한 실행은 실패한 GenAI 스팬입니다. 텔레메트리가 늦게 도착해도 놓치지 않도록 평가 창(15분)을 평가 주기(5분)보다 길게 잡았습니다 — 같은 사건이 최대 3번 평가됩니다.

#!/bin/sh
# 에이전트 알림 2개: 느린 실행(콜드 스타트 포함 8초 초과) · 실패한 실행. 사용: MAIL=<수신 이메일> sh scripts/alerts.sh
# 텔레메트리가 늦게 도착해도 놓치지 않도록 평가 창(15분)을 평가 주기(5분)보다 길게 잡았다 — 같은 사건이 최대 3번 평가된다.
set -eu
RG="$AZURE_RESOURCE_GROUP"; APPI_ID=$(az monitor app-insights component show -g "$RG" -a "appi-$AZURE_ENV_NAME" --query id -o tsv)
az monitor action-group create -g "$RG" -n ag-agent-latency --short-name agentlat --action email owner "$MAIL" -o none
AG=$(az monitor action-group show -g "$RG" -n ag-agent-latency --query id -o tsv)

SLOW=$(cat <<'KQL'
let hosted = requests | where cloud_RoleName == "agentsv2" | distinct agent = tostring(customDimensions["gen_ai.agent.name"]);
union
  (requests | where cloud_RoleName == "agentsv2" and customDimensions["gen_ai.operation.name"] == "invoke_agent"
   | project total_ms = duration + coalesce(toint(customDimensions["hosted_agent.latency.platform_preprocessing_ms"]), 0) + coalesce(toint(customDimensions["hosted_agent.latency.infra_setup_ms"]), 0) + coalesce(toint(customDimensions["hosted_agent.latency.container_readiness_ms"]), 0)),
  (dependencies | where cloud_RoleName == "responsesapi" and customDimensions["gen_ai.operation.name"] == "invoke_agent" and tostring(customDimensions["gen_ai.agent.name"]) !in (hosted)
   | project total_ms = duration)
| where total_ms > 8000
KQL
)
FAILED='dependencies | where success == false and isnotempty(customDimensions["gen_ai.operation.name"])'

az monitor scheduled-query create -g "$RG" -n agent-run-slow --scopes "$APPI_ID" --action-groups "$AG" -o none \
  --condition "count 'Q' > 0" --condition-query Q="$SLOW" --window-size 15m --evaluation-frequency 5m --severity 3
az monitor scheduled-query create -g "$RG" -n agent-run-failed --scopes "$APPI_ID" --action-groups "$AG" -o none \
  --condition "count 'Q' > 0" --condition-query Q="$FAILED" --window-size 15m --evaluation-frequency 5m --severity 2
